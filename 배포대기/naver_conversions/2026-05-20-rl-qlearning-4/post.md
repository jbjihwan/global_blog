안녕하세요! 파이썬과 Webots 시뮬레이터로 구현하는 초경량 표 기반 강화학습(Tabular Q-Learning) 자율주행 시리즈 4편입니다.

강화학습 훈련을 돌릴 때 나오는 그래프를 보면 보상이 계속 오르내립니다. 그 이유는 로봇이 여전히 새로운 길을 기웃거리며 무작위 행동을 섞는 '입실론 탐색(Epsilon Exploration)'을 하고 있기 때문입니다.

하지만 **실제 공장이나 물류창고에 로봇을 투입할 때는 절대 '무작위 탐색'을 시키면 안 됩니다.** 실수로 벽에 박거나 낭떠러지로 떨어지면 막대한 재산 피해가 발생하니까요!

실전에 투입되는 로봇은 탐색률을 0%로 완전히 끄고 오직 학습된 지식 중 최고 점수만을 골라 움직이는 **'결정론적 정책(Deterministic Greedy Policy)'**으로 주행해야 합니다.

이번 포스팅에서는 학습된 가중치로 로봇의 진짜 주행 실력을 검증하는 **정량 평가 파이프라인(`evaluate_qlearning.py`)** 구축 과정과, 딥러닝 신경망을 쓰는 DQN(Deep Q-Network), SARSA와의 맞대결 벤치마크 결과를 공유합니다!

## 1. 탐색률 0% 결정론적 평가 파이프라인

훈련이 끝난 뒤 저장된 `648 4` 크기의 가치 파일(`qlearning_qtable.npy`)을 불러와, 순수 추론 모드로 로봇을 주행시킵니다:

```python
# evaluate_qlearning.py - 결정론적(Greedy) 평가 핵심 로직
agent = QLearningAgent()
agent.load("qlearning_qtable.npy") # 학습된 Q-Table 로드

for ep in range(30): # 30회 독립 주행 시험
    state = env.reset()
    for t in range(150):
        # deterministic=True: 탐색 없이 오직 argmax Q(s, a)만 선택!
        action = agent.act(state, deterministic=True)
        next_state, reward, done, info = env.step(action)
        
        # 주행 거리, 충돌 여부, 벽 근접 위기(Near-miss) 정밀 기록
        record_telemetry(info)
        if done: break
```

단순히 "목표에 도달했는가?"만 따지는 것이 아니라, 로봇이 벽에 얼마나 아슬아슬하게 스쳐 지나갔는지 나타내는 **근접 위기(Near-miss, 벽과의 거리 `\le 15cm`)** 횟수와, 이론적 직선 거리 대비 실제 이동 경로의 비율인 **경로 효율성(Path Efficiency)**을 정밀 측정했습니다.

## 2. 알고리즘 맞대결: Tabular Q-Learning vs DQN vs SARSA

많은 분들이 *"요즘 세상에 딥러닝(DQN)을 써야지, 옛날 방식인 표(Table) 기반 Q-Learning을 왜 쓰냐?"*고 의문을 가집니다.

하지만 제한된 임베디드 실내 로봇 환경에서 직접 벤치마크를 돌려본 결과는 놀라웠습니다:

| 비교 지표 | Tabular Q-Learning (본 프로젝트) | DQN (심층 Q-신경망) | SARSA (온폴리시 TD) |
| :--- | :---: | :---: | :---: |
| **목표 도달 성공률** | **93.3%** | 86.7% | 80.0% |
| **추론 1스텝 소요 시간** | **0.002 ms** (`O(1)`) | 1.850 ms (PyTorch 순전파) | 0.002 ms (`O(1)`) |
| **메모리 점유율** | **20 KB** (작은 npy 파일) | 150 MB (PyTorch + CUDA 가중치) | 20 KB |
| **벽 근접 위기 횟수** | 1.2회 (안정적 우회) | 3.8회 (센서 과적합) | 0.8회 (지나치게 소극적) |

- **DQN의 한계**: 딥러닝 신경망은 풍부한 연속 입력을 다룰 수 있지만, 작은 실내 맵에서는 오히려 신경망의 비선형성 때문에 센서 값에 민감하게 과적합되어 벽 모서리에서 버벅거리는 현상이 발생했습니다.
- **Q-Learning의 압승**: 반면 648개 상태로 이산화된 Q-Table은 메모리를 고작 20KB밖에 쓰지 않으면서도, 0.002ms라는 압도적인 반응 속도로 벽을 부드럽게 돌아나갔습니다!
