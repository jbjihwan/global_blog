## 1. 장기 컨텍스트의 딜레마와 계층적 메모리의 필요성

단순히 LLM의 물리적 컨텍스트 윈도우를 늘리는 것만으로는 기억 문제를 해결할 수 없습니다:
- **주의력 분산 (Lost-in-the-Middle):** 트랜스포머의 셀프 어텐션은 시퀀스가 길어질수록 어텐션 분포가 평탄화되어 긴 프롬프트 중간의 세부 정보를 간과하기 쉽습니다.
- **비용 폭증:** 매 턴마다 수십만 토큰을 다시 전송하는 것은 경제적으로 감당할 수 없습니다.
- **정적 휘발성:** 세션이 끝나면 활성화 상태가 사라지므로, 에이전트 스스로 지속적인 자아를 구축하지 못합니다.

따라서 최신 에이전트 아키텍처는 고속의 **작업 컨텍스트(Working Context)**와 대용량의 **장기 저장소(Long-Term Storage)**를 분리하는 **Hierarchical Context Management**를 채택합니다.

```text
┌─────────────────────────────────────────────────────────────────────────┐
│               에이전트 기억 시스템의 3대 추상화 계층                    │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
       ┌─────────────────────────────┼─────────────────────────────┐
       ▼                             ▼                             ▼
┌──────────────────────────┐  ┌──────────────────────────┐  ┌──────────────────────────┐
│   소프트웨어 제어 계층   │  │    신경망 표현 계층      │  │    인프라 시스템 계층    │
│         (MemGPT)         │  │       (Cartridges)       │  │       (CacheBlend)       │
├──────────────────────────┤  ├──────────────────────────┤  ├──────────────────────────┤
│ • 운영체제식 가상 페이징 │  │ • Self-Study 지식 증류   │  │ • 다중 청크 RAG 병합     │
│ • 메인 컨텍스트 (RAM)    │  │ • 연속형 KV 캐시 임베딩  │  │ • 선택적 KV 재계산 (15%) │
│ • 아카이브 벡터 DB (Disk)│  │ • 메모리 사용량 38.6배↓  │  │ • RoPE 좌표 회전 복원    │
│ • 자율 축출 및 재귀 요약│  │ • 서빙 처리량 26.4배↑    │  │ • TTFT 대기시간 3.3배 단축│
│ • 심층 기억 회상(DMR) 92%│  │ • 레고 블록식 모듈 결합 │  │ • F1 정확도 손실 < 0.01  │
└──────────────────────────┘  └──────────────────────────┘  └──────────────────────────┘
```

## 2. 소프트웨어 제어 계층: MemGPT (UC Berkeley 2023)

운영체제(OS)는 한정된 물리 RAM을 가지고 MMU(메모리 관리 장치)를 통해 하드디스크와 페이지를 교환(Swap-in / Swap-out)함으로써 가상 메모리 공간을 제공합니다.

UC 버클리 연구진이 발표한 **MemGPT Long-Term Memory**는 이 고전 OS의 지혜를 언어 모델에 그대로 투영했습니다:
> **"LLM의 프롬프트 컨텍스트 윈도우는 메인 메모리(RAM)이다. 그 밖의 모든 벡터 DB와 SQL은 하드디스크이다. 그렇다면 모델 자신이 스스로 함수 호출(Function Calling)을 통해 필요 없는 기억을 디스크로 보내고, 필요한 기억을 다시 RAM으로 불러오게 만들면 되지 않는가!"**

```text
    ┌────────────────── [Main Context (RAM, 8k~128k 토큰 한계)] ──────────────────┐
    │ 1. System Instructions : 시스템 정체성 및 메모리 조작 함수 매뉴얼 (Read-only)     │
    │ 2. Working Context     : 사용자 인적사항, 핵심 페르소나 요약본 (Read/Write)      │
    │ 3. FIFO Message Queue  : 최근 대화 큐 + (헤드에 위치한 재귀적 과거 요약본)       │
    └────────────────────────────────────────────────────────────────────────────┘
                               ▲                      │
               (스왑 인 / Search)│                      │ (스왑 아웃 / Eviction & Flush)
                               │                      ▼
    ┌───────────────── [External Context (Disk, 무제한 스토리지)] ────────────────┐
    │ 1. Recall Storage   : 타임스탬프가 찍힌 전체 대화 메시지 원문 DB (PostgreSQL)  │
    │ 2. Archival Storage : 수백만 건의 대형 문서 벡터 임베딩 DB (HNSW pgvector)    │
    └────────────────────────────────────────────────────────────────────────────┘
```

### 자율적 메모리 페이징 메커니즘
- **메모리 압박 경고 (70%):** 윈도우의 70%가 차면 시스템이 *"경고: 메모리가 70% 차올랐습니다. 축출되기 전에 중요한 정보는 `working_context.replace()`로 저장하십시오"*라는 경고를 큐에 주입합니다.
- **자동 플러시 및 재귀적 요약 (100%):** 윈도우가 가득 차면 가장 오래된 50%의 대화를 잘라내되, 이전 요약본과 잘려 나갈 메시지를 결합하여 **새로운 재귀적 요약본(Recursive Summary)**을 작성해 큐 맨 앞에 둡니다.
- **벤치마크 결과:** 수십 번의 세션을 넘나드는 깊은 기억 회상(DMR)에서 일반 GPT-4는 32.1%에 불과했으나, MemGPT는 **92.5%**를 기록했습니다.

## 3. 신경망 표현 계층: Cartridges (2025)

텍스트 토큰을 외부 DB와 주고받는 방식은 수만 토큰을 읽을 때마다 막대한 Prefill 지연을 유발합니다.

2025년 발표된 **Cartridges Modular Agent Memory**는 충격적인 접근을 취합니다:
> **"왜 텍스트 토큰을 그대로 들고 다니는가? 500페이지의 문서를 오프라인에서 스스로 공부(Self-Study)하게 하여, 단 50~100개의 '학습 가능한 연속 KV 캐시 벡터(Cartridge)'로 농축해 버리면 되지 않는가!"**

- **단순 다음 토큰 예측(NTP)의 한계:** 문장을 달달 외우는 암송(Recitation)은 잘하지만 응용 질문에는 전혀 답하지 못하는 '단순 암기 증후군' 발생.
- **Self-Study & 컨텍스트 증류의 해법:**
  - 모델 자신에게 5가지 원형의 Q&A 가상 대화를 대량으로 생성하게 함.
  - 500쪽 원문을 전부 넣은 교사 모델의 출력 확률 분포를, 압축된 **카트리지 Z (50~100개 토큰)**만을 꽂은 학생 모델이 모방하도록 **KL 발산 손실**로 가중치 역전파 업데이트.
- **결과:** LongHealth 벤치마크에서 원문 전체를 넣은 것과 동등한 정확도를 유지하면서도 **메모리 사용량을 38.6배 절감**, **추론 처리량을 26.4배 향상**시켰습니다!

## 4. 인프라 시스템 계층: CacheBlend (EuroSys 2025)

RAG 에이전트가 10개의 서로 다른 문서 조각(Chunk)을 검색해서 프롬프트에 이어 붙일 때:
- **접두사 캐싱(Prefix Caching):** 첫 번째 조각만 캐시를 재활용할 수 있어 TTFT가 3~6초 소요.
- **단순 전체 캐시 재사용:** 조각 간 상호작용(Cross-Attention)이 무시되어 답변 정확도가 50% 이하로 붕괴.

EuroSys 2025에서 발표된 **CacheBlend KV Cache Merging**은 **선택적 KV 재계산(Selective KV Recompute)**으로 이 문제를 완벽히 해결했습니다:

```text
[검색된 문서 조각 A, B, C의 사전 계산된 KV 캐시 로드]
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  CacheBlend 레이어별 선택적 재계산                           │
│  1. 상위 15% 토큰 선별: 교차 어텐션 편차가 큰 토큰 (HKVD)     │
│  2. 선별된 15% 토큰만 새로 어텐션 연산 실행                   │
│  3. 나머지 85% 토큰은 사전 계산된 KV 캐시 그대로 병합         │
│  4. RoPE 위치 임베딩 회전 복원 적용                        │
└─────────────────────────────────────────────────────────────┘
                       │
                       ▼
[초고속 Prefill 완료!] (TTFT 3.3배 단축, 정확도 손실 0.01 이하)
```

- **주의력의 희소성:** 여러 문서를 섞었을 때 다른 문서의 영향을 받아 값이 크게 변하는 토큰은 **전체의 10~15%에 불과**합니다.
- **레이턴시 숨기기 (Latency Hiding):** 15%를 재계산하는 수 밀리초 동안, 백그라운드에서는 NVMe SSD로부터 다음 레이어 캐시를 비동기로 읽어와 계산 시간을 I/O 뒤에 완전히 숨겼습니다.
- **결과:** 첫 응답 출력 시간(TTFT)을 **3.3배 단축**시켰고, 서빙 처리량을 **5배 향상**시켰습니다.
