## 📌 한눈에 보는 핵심 요약 (TL;DR)

1. **알림 피로(Alert Fatigue) 극복**: 연간 수십만 건의 조달 데이터 중 85% 이상을 차지하는 A4 용지, 청소용품 등 정상 소모품 노이즈를 걸러내기 위해 **'3차원 표적 분할 매니저(SectorPartitionManager)'**를 설계하여 노이즈를 85% 이상 사전 필터링.
2. **사전 예방 설계**: 공공 API의 잦은 타임아웃과 규격 변동에 대비해 **SQLite 미감사 격리 버퍼 큐와 지수 백오프(Exponential Backoff)** 재시도 계층 사전 구축.
3. **실제 겪은 3대 돌발 오류 해결**:
   - 나라장터 레거시 API의 **캐럿(`^`) 복합 구분자 폭탄**으로 인한 스키마 붕괴 ➔ 정규식 복합 파서 및 엄격한 타입 검증기로 해결.
   - 수천 개 지식 그래프 노드 일괄 렌더링 시 **브라우저 화면 멈춤(Freeze)** ➔ **Depth-1 Ego-Network 서브그래프 가상화**로 렌더링 시간 98% 단축 (12초 ➔ 0.05초).
   - 실시간 폴링 시 **중복 계약 적재 및 중복 경보 발행** ➔ **SHA-256 Fingerprint Hash** 기반 멱등성(Idempotent) 파이프라인으로 해결.
4. **산출물**: 조달청 라이브 연동, 10개년 판례 DB, HWPX 즉석 분석기, 인터랙티브 지식그래프를 탑재한 **감사관 종합 웹 포털 v2.0** 완성 및 13개 통합 테스트 100% PASS.

## 1. 개발 전 '예상했던 2대 난제'와 사전 예방책

### 🎯 난제 1: 단순 소모품 데이터 폭탄과 알림 피로 (Alert Fatigue)
* **예상 문제**:
  - 나라장터에는 복사용지, 화장지, 볼펜 등 정상적인 소액 구매가 전체 건수의 대다수를 차지합니다.
  - 여기에 LLM과 지식그래프를 무차별 적용하면 막대한 API 비용이 나가고, 단가가 조금만 튀어도 감사관에게 알림을 쏟아내어 결국 시스템을 외면하게 만듭니다.
* **사전 예방 설계**:
  - 우리는 데이터를 3개의 축으로 교차 분석하는 **3차원 표적 분할 매니저(SectorPartitionManager)**를 사전 설계했습니다.
    $$\text{Target Sector} = \text{기관 특성} \times \text{비목 유형} \times \text{계약 방식}$$
  - **기관 특성**: 중앙부처 vs 공공기관 vs 지자체
  - **비목 유형**: 단순 물품 vs 시설 공사 vs SW 용역/행사 대행
  - **계약 방식**: 일반경쟁 vs 제한경쟁 vs 2천만 원 이하 수의계약
  - 이 매트릭스를 통해 정상 소모품 노이즈를 **85% 이상 사전에 걸러내고**, 부정부패 위험이 가장 높은 **Sector 1 (공공기관 ICT 2천만 원 이하 수의계약)** 등에만 고성능 AI 추론 엔진을 집중 투입했습니다.

### 🔌 난제 2: 공공데이터 API의 잦은 타임아웃과 규격 변동
* **예상 문제**:
  - 정부 공공데이터포털(data.go.kr)은 트래픽이 몰리면 타임아웃이 잦고 전송이 중단될 수 있습니다. 외부 API의 불안정성이 내부 감사 파이프라인 크래시로 번지면 안 되었습니다.
* **사전 예방 설계**:
  - 외부 수신 계층과 내부 감사 엔진을 철저히 분리(Decoupling)했습니다.
  - API에서 데이터를 받는 즉시 로컬 SQLite **'미감사 격리 버퍼 큐'**에 임시 적재하고, 3회 지수 백오프(1초 ➔ 2초 ➔ 4초) 재시도 로직을 탑재하여 일시적 네트워크 장애에도 파이프라인이 멈추지 않도록 격리했습니다.

## 2. 실제 개발 중 마주친 '3대 돌발 오류'와 치열한 해결기

하지만 실제 공공데이터 라이브 서버와 통신을 시작하자마자, 예상치 못했던 기상천외한 버그들이 터져 나왔습니다.

### 🚨 버그 1: 나라장터 API의 캐럿(`^`) 복합 구분자 폭탄
* **실제 증상**:
  - 나라장터 신규 계약 API(`ao/CntrctInfoService`)를 연결하자마자 JSON 파서가 크래시되거나, 계약금액 자리에 엉뚱한 문자열이 들어가 데이터가 오염되었습니다.
* **원인**:
  - 과거 레거시 시스템과의 호환성 때문에, 일부 필드가 단일 값이 아니라 **복수 계약 정보를 캐럿(`^`) 기호로 줄줄이 엮어 전송**하고 있었습니다 (예: `품목A^품목B^품목C`, `1000^2500^3000`).
* **해결 방법**:
  - 캐럿 복합 필드를 감지하여 1:N 구조로 평탄화(Flattening)하는 **`SplitCaretRecord` 정규식 파서**와 엄격한 타입 검증기(Type Validator)를 제작하여 파이프라인 전면에 배치했습니다.

---

### 🚨 버그 2: 수천 개 노드 일괄 렌더링 시 브라우저 멈춤 (Freeze Lock)
* **실제 증상**:
  - 감사관 웹 포털 v2.0에서 Vis.js 네트워크 그래프를 띄우자, 브라우저 탭의 메모리가 폭증하며 화면이 완전히 멈춰버렸습니다.
* **원인**:
  - 수천 개의 기업, 주소, 계약 노드 사이의 반발력과 인력을 브라우저 싱글 스레드가 실시간으로 물리 연산하느라 렌더링 루프가 100% 점유된 것이었습니다.
* **해결 방법**:
  - **위험도 기반의 'Depth-1 Ego-Network 서브그래프 가상화'**를 도입했습니다!
  - 초기 화면에는 고위험(CRITICAL/HIGH) 플래그가 붙은 **핵심 의혹 노드 30개만 선별 렌더링**하고, 사용자가 특정 노드를 클릭했을 때만 1차 이웃 노드들을 동적으로 페칭(Lazy Loading)하도록 바꾸었습니다.
  - 그 결과 초기 렌더링 속도가 **12초에서 0.05초로 98% 단축**되었습니다!

---

### 🚨 버그 3: 실시간 동기화 시 중복 계약 적재 및 중복 경보 발행
* **실제 증상**:
  - 데일리 모니터링 데몬이 주기적으로 최신 데이터를 폴링할 때, 며칠 전 이미 감사하여 처분요구서까지 뽑았던 계약 건이 오늘 또 '새로운 이상 거래'로 감지되어 중복 Flash Alert를 울렸습니다.
* **원인**:
  - 조달청 API에서 차수 변경이나 단순 결제 상태 갱신이 일어날 때마다 API 응답 순서가 뒤바뀌면서 단순 시퀀스 번호 기반 중복 체크가 무력화되었습니다.
* **해결 방법**:
  - 발주기관 코드 + 수주기업 사업자번호 + 원 계약일자 + 계약금액을 조합하여 고유한 **SHA-256 Fingerprint Hash**를 생성하고, DB 적재 단계에서 멱등성(Idempotency Key)을 보장하도록 수정했습니다.

## 3. 완성된 감사관 종합 웹 포털 v2.0 & 13개 전수 테스트 통과

트러블슈팅을 거쳐 완성된 웹 포털(`http://localhost:8088`)은 현장 감사관을 위한 5대 강력한 기능을 제공합니다:

1. **지식그래프 인터랙티브 뷰**: 서초구/강남구 동일 주소지를 공유하는 페이퍼컴퍼니 카르텔을 시각적으로 탐색.
2. **10개년 판례 지식베이스**: 감사원(BAI) 및 국회예산정책처(NABO) 공식 선례 검색 및 유사도 열람.
3. **HWPX 실시간 테이블 검증기**: 공공 서식 예산서를 드래그 앤 드롭하면 단가 뻥튀기를 0.1초 만에 하이라이트.
4. **감사 Dossier 출력기**: 법적 증거 효력을 갖춘 마크다운 보고서를 원클릭 다운로드.
5. **실시간 이상 평가기**: 신규 계약 정보를 입력하면 5단계 위험도와 위반 법조항을 즉석 도출.

우리는 `run_all_tests.py`를 통해 **13개 단위·통합 테스트 스위트를 100% 전원 PASS**하며 시스템의 무결성을 입증했습니다!
