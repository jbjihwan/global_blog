# [스탠포드 CS329A #2] 추론 시간 연산 확장: 사전 훈련 스케일링 법칙을 넘어 연산 최적 추론으로

안녕하세요! 글로벌 AI 기술 트렌드를 가장 깊이 있게 분석해 드리는 개발 블로그입니다.

지난 1편에서는 스탠포드 대학교의 2025년 가을 학기 최신 강의인 **CS329A: Self-Improving AI Agents (스스로 발전하는 AI 에이전트)**의 전체적인 로드맵과 패러다임 전환을 살펴보았습니다.

오늘 다룰 **제2강**은 현재 전 세계 AI 학계와 빅테크 연구실에서 가장 뜨거운 화두인 **"추론 시간 연산 확장 (Test-Time Compute Scaling / Inference-Time Scaling)"**입니다.

> **"모델을 더 똑똑하게 만들려면 오직 더 큰 모델을 훈련시키는 방법뿐일까?"**

과거 수년간의 상식은 "수천억 원을 들여 모델 파라미터를 키우고 수조 개의 데이터를 학습시키는 것(사전 훈련 스케일링)"이었습니다. 하지만 이미 훈련이 끝난 고정된 모델에게 질문을 던졌을 때, 0.05초 만에 성급히 대답하는 대신 **10초, 1분 동안 스스로 생각하고, 가설을 검증하며, 오류를 고치게 한다면** 어떤 일이 벌어질까요?

오늘 우리는 버클리-구글의 *Large Language Monkeys*, 스탠포드 Charlie Snell 연구팀의 *Compute-Optimal Scaling*, 그리고 *Archon* 프레임워크를 통해 이 질문의 해답을 명쾌하게 파헤쳐 보겠습니다!

## 1. 사전 훈련 스케일링(Pre-training Scaling)이 직면한 3가지 한계

기존의 딥러닝은 모델 파라미터(N)와 훈련 데이터(D)를 늘릴수록 손실(Loss)이 감소한다는 카플란(Kaplan)과 친칠라(Chinchilla)의 멱법칙(Power Law)에 의존해 왔습니다. 하지만 GPT-4급 이상으로 모델이 커지면서 세 가지 거대한 물리적 암초를 만났습니다:

1. **인터넷 텍스트 데이터의 고갈:** 인간이 생성한 고품질 웹 데이터는 약 10^14 토큰으로 유한합니다. 검증기 없는 합성 데이터를 무작정 재학습시키면 모델 붕괴(Model Collapse)가 일어납니다.
2. **지수적으로 폭증하는 비용:** 성능을 단 1% 올리기 위해 10배의 GPU 연산을 쏟아부어야 하므로, 천문학적인 전기세와 자본이 듭니다.
3. **단일 순방향 패스(Forward Pass)의 맹점:** 모델 크기가 아무리 커도 기존 디코딩은 한 단어씩 직진으로 뱉어낼 뿐입니다. 되돌아보기(Backtracking)나 가설 수정이 불가능합니다.

## 2. 무한 원숭이 정리의 귀환: Large Language Monkeys

2024년 말, UC 버클리와 구글 리서치는 매우 흥미로운 논문을 발표했습니다: **《Large Language Monkeys: Scaling Inference Compute with Repeated Sampling》**.

하나의 문제에 대해 모델에게 온도를 주어 독립적인 답변 후보를 1개부터 최대 10,000개까지 생성하게 하고, 그중 정답이 존재하는지를 측정한 것입니다.

### 📊 충격적인 실험 결과: 작은 모델의 대반란!
* **SWE-bench Lite (실제 깃허브 버그 수정 벤치마크):**
  * 오픈소스 모델 `DeepSeek-Coder-V2`를 단 1번 돌렸을 때의 성공률은 **15.9%**에 불과했습니다.
  * 하지만 250번 샘플링하자 성공률은 **56.0%**로 폭등했습니다!
  * 이는 당시 단일 실행 최강자였던 GPT-4o와 Claude 3.5 Sonnet의 앙상블(43.0%)을 **무려 13%p나 압도한 수치**였습니다.
* **CodeContests (극난도 알고리즘 경시대회):**
  * 경량 모델 `Gemma-2B`의 단일 정답률(pass@1)은 **0.02%**로 사실상 0이었습니다.
  * 하지만 10,000번 샘플링하자 정답률이 **7.1%**로 무려 **355배 폭증**했습니다.
* **비용 효율성의 역전:**
  * SWE-bench에서 DeepSeek-Coder-V2로 5번 샘플링(29.62%)하는 비용은 **$10.80**였습니다.
  * 반면 GPT-4o 단일 실행(24%)은 **$39.00 (3.6배 비쌈)**, Claude 3.5 Sonnet(26.7%)은 **$51.00 (4.7배 비쌈)**이 들었습니다!
  * 즉, **"작고 저렴한 모델을 여러 번 돌리는 것"이 "가장 크고 비싼 모델을 한 번 돌리는 것"보다 훨씬 우월하다**는 사실이 증명된 것입니다.

### ⚠️ 하지만 마주한 암초: 커버리지-정밀도 격차 (Coverage-Precision Gap)
단위 테스트가 있는 코딩 분야에서는 250개 중 1개만 테스트를 통과하면 정답을 골라낼 수 있습니다. 하지만 **외부 검증기가 없는 일반 수학이나 주관식 문제**에서는 어떨까요?

MATH 데이터셋에서 Llama-3-8B는 10,000개 샘플링 시 **98.44%의 확률로 정답 풀이를 포함**하고 있었습니다. 하지만 다수결 투표(Majority Voting)를 시키면 정답률은 **41.41%**에 그쳤습니다. 

> **핵심 교훈:** 무작정 샘플만 많이 뽑는 것은 건초더미의 크기를 키우는 것과 같습니다. 건초더미 속에 바늘(정답)이 들어갈 확률이 99%가 되더라도, 그 바늘을 짚어낼 수 있는 정밀한 자석(검증기, Verifier)이 없다면 무용지물입니다.

## 3. 스넬(Snell)의 연산 최적 확장 법칙 (Compute-Optimal Scaling)

그렇다면 무작정 주사위만 10,000번 던지는 대신, 주어진 계산 예산 안에서 가장 영리하게 추론 연산을 소비하는 방법은 무엇일까요?

스탠포드와 UC 버클리의 Charlie Snell 연구팀은 **《Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters》** 논문에서 해답을 제시했습니다.

### 💡 문제 난이도에 따른 최적 배분의 황금률
Snell 연구팀은 추론 기법을 **제안자(Proposer)**와 **검증자(Verifier)**의 두 축으로 나눈 뒤, 문제 난이도에 따라 전략을 동적으로 바꾸었습니다:

1. **쉬운 문제 (Bin 1-2): 순차적 수정(Sequential Revision)의 압승**
   * 쉬운 문제는 모델이 이미 정답에 근접해 있으므로, "방금 쓴 풀이의 사소한 오타나 부호 실수를 고치게 하는 수정"이 가장 효율적입니다.
   * 오히려 쉬운 문제에 복잡한 트리 탐색을 적용하면 검증기 노이즈가 누적되어 성능이 떨어집니다.
2. **어려운 문제 (Bin 3-5): 빔 서치(Beam Search)와 PRM의 압승**
   * 고난도 문제는 한 번 잘못된 길로 들어서면 자가 수정이 어렵습니다. 따라서 단계별 보상 모델(PRM)을 통해 유망한 경로만 남기고 가지치기하는 탐색이 압도적인 성능을 냅니다.
3. **4배의 연산 절감:**
   * 난이도에 맞게 쉬운 문제엔 Revision을, 어려운 문제엔 PRM 탐색을 배치하는 Compute-optimal 전략은 단순 샘플링 대비 **동일 정확도를 달성하는 데 연산량을 4배(4x)나 절감**했습니다.

### 🔥 14배 파라미터 모델과의 정면 승부
스넬 교수의 가장 놀라운 실험은 **"14배 더 큰 모델" vs "작은 모델 + 14배의 추론 연산"**의 대결이었습니다.
* GSM8K와 MATH의 중급 문제까지는, 작은 모델에 추론 연산을 집중시키는 것이 14배 거대한 모델을 앞질렀습니다!
* 단, 인간도 실마리를 못 잡는 극난도 문제에서는 여전히 사전 훈련된 모델 자체의 내재적 지능(파라미터)이 필요했습니다.

## 4. 실전 시스템 엔지니어링: Archon 모듈형 에이전트

이 이론을 실제 서비스로 어떻게 구현할까요? **Archon** 프레임워크는 LLM 컴포넌트를 레고 블록처럼 5개 계층으로 조립했습니다:

1. **생성기 (Generator):** 다양한 프롬프트와 온도로 후보군 대량 생성
2. **비평기 (Critic):** 각 후보 답변의 논리적 오류와 취약점을 조목조목 지적
3. **순위기 (Ranker):** 토너먼트 방식으로 최선의 답변 정렬
4. **융합기 (Fuser):** 상위 후보들의 핵심 아이디어만 뽑아 하나의 완벽한 답변으로 재합성 (+8.9% 향상)
5. **검증기 (Verifier):** 코딩 문제의 경우 단위 테스트를 직접 작성해 샌드박스에서 실행 검증 (+56% 향상)

베이지안 최적화를 통해 9,576개의 아키텍처 중 비용과 지연 시간에 딱 맞는 최적의 파이프라인을 자동으로 찾아냅니다!

## 5. OpenAI o1의 비밀: 생각의 사슬(Thinking)의 정체

최근 화제가 된 OpenAI o1이나 DeepSeek-R1이 답변 전에 길게 출력하는 "생각(Thinking Process)"은 마법이 아닙니다.

오늘 우리가 배운 **"내부적인 CoT 생성 + 순차적 오류 수정(Revision) + PRM 방식의 단계별 가지치기"**가 단일 모델 가중치 안에 녹아들어 작동하는 **추론 시간 연산 확장의 결정체**인 것입니다!

## 6. 핵심 요약 및 시사점

1. **지능 확장의 새로운 축:** AI 발전은 사전 훈련에만 갇혀 있지 않습니다. 추론 시간 연산 확장은 소형 모델도 빅테크 모델을 이기게 만드는 강력한 무기입니다.
2. **검증기(PRM)의 중요성:** 샘플만 많이 뽑는 것은 무의미하며, 정확한 정답을 걸러내는 정밀한 검증기가 있어야만 커버리지가 성능으로 전환됩니다.
3. **난이도 적응형 최적화:** 쉬운 문제엔 자가 수정을, 어려운 문제엔 PRM 기반 탐색을 사용하는 것이 4배 더 효율적입니다.
