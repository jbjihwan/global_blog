5월 19일과 20일 이틀 동안은 3차 파인튜닝(fine_tuning_3)의 평가 자동화와 더불어, 실제 앱(App) 서비스 구축을 위한 백엔드/프론트엔드 기능 고도화 작업이 병렬로 진행되었습니다.

3차 파인튜닝 (fine_tuning_3) 마무리와 자동화 스크립트​

이전 파인튜닝에서 얻은 인사이트를 바탕으로, 지식그래프와 온톨로지 개념을 의식하며 세팅했던 3차 파인튜닝의 학습이 완료되었습니다.

"fine_tuning_3 폴더의 실험 모델들 중 Best Eval을 가진 체크포인트를 선별하여 adapter 폴더 내 파일을 교체하고 결과를 보고해 줘." "fine_tuning_3에서도 추론과 평가를 병렬로 진행하는 run_test_20_30.sh 파일을 작성해 주세요."

이전처럼 사람이 일일이 폴더를 뒤지며 체크포인트를 복사하는 대신, 인공지능(AI)에게 스크립트를 짜도록 지시하여 가장 성능이 좋은 모델 가중치(Best Checkpoint)를 자동으로 추출해 adapter 폴더에 세팅했습니다. 그리고 병렬 추론 스크립트인 run_test_20_30.sh를 실행하여 4개의 Alias 모델에 대한 평가를 백그라운드 서버에 던져두었습니다.

백엔드/프론트엔드: 챗봇 DB 저장과 게시판 기능 완성​

모델이 서버에서 열심히 추론을 돌리는 동안, 로컬 환경에서는 mental-health DB와 앱 연동 작업에 박차를 가했습니다.

"seed_data.sql 정보 요약. users의 pw가 무엇이지? Test1234! 인가? 현재 내가 이 sql을 적용하려던 db가 뭐였지?"

지난번 401 Unauthorized 에러로 골치를 썩였던 로그인 문제를 뚫어내기 위해 seed_data.sql을 뜯어보며 비밀번호 해싱과 유저 데이터를 철저히 검증했습니다.

그 결과, 5월 20일 오후 뜻깊은 Git 커밋(Commit) 하나를 남길 수 있었습니다. feat: 챗봇 DB 저장, 게시판 페이지네이션, 감정일기 필터 추가

드디어 저희가 파인튜닝한 거대 언어 모델(LLM) 챗봇의 대화 기록이 DB에 정식으로 저장되기 시작했습니다! 더불어 사용자들끼리 소통할 수 있는 커뮤니티 게시판의 페이지네이션(Pagination) 기능과, 매일매일의 기분을 기록하는 감정일기 필터 기능까지 성공적으로 프론트엔드에 얹혔습니다.

눈에 보이지 않던 거대한 파인튜닝 모델이 비로소 모바일 앱이라는 예쁜 그릇에 담기기 시작한 감격스러운 순간이었습니다.

jbgih

제가 이전에 "5월 13일이 마음지기 5월 개발의 마지막일 것"이라고 착각했던 것을 정정합니다! 5월 17일, 어마어마한 양의 백엔드 연동 테스트와 보고서 작업이 몰아쳤습니다.

인공지능(AI)를 활용한 파인튜닝 결과 보고서 자동화​

2차 파인튜닝(fine_tuning_2)의 방대한 결과 그래프(common, daily 데이터셋 비교 등)를 하나씩 사람이 분석해서 쓰기에는 시간이 너무 부족했습니다.

"모델들의 추론 결과를 비교하는 보고서를 작성하기 위한 프롬프트를 만들어주세요. 프롬프트 자체를 report_prompt.md로 저장하고, 이에 따라 보고서 작성을 수행해 줘." "내가 바란 보고서는 .md 형식이 아닌 .docx 형식을 희망했습니다."

AI에게 결과 지표를 해석하게 하고, 보고서 초안을 자동으로 작성하는 프롬프트 엔지니어링을 시도했습니다. 결과적으로 AI가 각 모델의 장단점과 Alpha 값에 따른 차이를 분석해 훌륭한 워드(.docx) 보고서 초안을 뽑아주었습니다.

백엔드 DB 연동과 401 Unauthorized의 늪​

보고서가 마무리되자마자 프론트엔드와 백엔드의 시스템 안정성을 테스트하기 위해 backup.sql 데이터를 로컬 PostgreSQL DB에 밀어 넣는 작업을 시작했습니다.

"backup.sql에 데이터를 넣고 싶습니다. 목적: Frontend, Backend 작동 및 시스템 안정성 테스트." "backend, frontend 구동 후 접속 성공했으나 메뉴들을 선택해도 반응이 없음" "이메일 또는 비밀번호가 틀렸어요... INFO: 127.0.0.1:54446 - POST /auth/login 401 Unauthorized"

DB 덤프를 성공적으로 밀어 넣고 웹에 접속까지는 성공했지만, 로그인이 되지 않는 401 Unauthorized 에러 지옥에 빠졌습니다. debug_login.py를 만들고 uvicorn 서버를 껐다 켜며 수십 번의 트러블슈팅을 진행했습니다. 비밀번호 해싱 방식이 달랐던 건지, DB 마이그레이션이 꼬인 건지 로그를 뒤지며 밤을 새우다시피 했습니다.

지식그래프(Knowledge Graph)의 도입 고민​

"우리 프로젝트의 목적은 효율적으로 자살예방 챗봇을 만드는 것입니다. 요즘 하네스, 온톨로지, 지식그래프 등을 사용하는 기법이 떠오르는데, 거대 언어 모델(LLM) 하나만 집중하는 것보다 더 나은 안정성을 가진 챗봇을 만들 수 있을 것 같습니다."

밤늦은 시간, 단순 LLM 파인튜닝의 한계를 극복하기 위해 온톨로지와 지식그래프(Knowledge Graph)를 융합하는 방안을 새롭게 고민하며 chatbot_design_prompt.md를 설계하기 시작했습니다. 5월 중순을 넘어가며 프로젝트의 스케일이 점점 더 거대해지고 있습니다!
