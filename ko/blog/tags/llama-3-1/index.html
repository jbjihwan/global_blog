4월 9일, 어제 야심 차게 완성한 Colab 노트북을 이용해 드디어 인공지능 모델(Llama 3.1)의 첫 학습(파인튜닝)을 시도했습니다. 하지만 현실은 역시 호락호락하지 않았고 수많은 에러와 마주해야 했습니다. 동시에 캡스톤 디자인 6주차 중간발표 자료까지 만들어야 했던 험난한 하루였습니다.

Colab 파인튜닝 에러와의 끝없는 사투​

  • 문제: 어제 만든 llama31_finetuning_colab.ipynb를 실행하자마자 각종 에러가 쏟아졌습니다.
  • 과정:

    "llama31_finetuning_colab (3).ipynb에서 M1 파인튜닝 진행 중 오류가 발생한 이유가 무엇일까요?" "실행한 결과에 eos_token이 포함되어 있습니다. 왜 이런 문제가 발생할까요?"

  • 결과: 인공지능(AI) 모델이 학습 데이터를 토해내는 과정에서 특수 토큰(eos_token) 처리가 제대로 되지 않는 문제, 메모리 오버플로우 문제 등이 연달아 발생했습니다. 발생한 에러 로그 전체를 Claude에게 복사해서 던져주고(Pasted text) 해결책을 받아 코드를 수정하는 과정을 수차례 반복했습니다. 결국 우여곡절 끝에 학습이 완료되었고, 학습데이터별학습결과.png라는 의미 있는 결과 그래프를 뽑아낼 수 있었습니다!

AI 비서의 발표 자료(PPT) 만들기​

  • 문제: 모델 훈련으로 밤을 새우고 있는데 당장 다음 주 발표를 위한 6주차 프론트엔드 및 데이터베이스 진행 상황 PPT를 만들어야 했습니다.
  • 과정:

    "캡디_6주차_Frontend.pptx는 지금까지 진행한 개요를 소개하는 이미지 모음입니다. 이를 활용하여 이번 주 진행 상황 발표 자료를 만들어주세요." "데이터베이스 설계의 Table들이 backend에 구현된 테이블의 관계를 참고하여 관계가 보이도록 표현해 줘... 표가 너무 크고 중구난방입니다. User 테이블을 중심에 배치해 주세요."

  • 결과: 놀랍게도 AI는 프론트엔드 이미지 스크린샷들을 엮어 발표 스크립트와 슬라이드 뼈대를 만들어 주었습니다. 심지어 제가 백엔드 코드를 기반으로 복잡한 데이터베이스 ERD(Entity Relationship Diagram)를 그려달라고 집요하게 피드백(User 중심 배치)을 주자, 완벽하게 데이터베이스 관계도까지 정리해서 설명해 주었습니다.

오늘은 Llama 3.1이라는 최신 언어 모델을 직접 내 손(과 AI의 머리)으로 튜닝해 보는 쾌감을 느낀 날입니다. 동시에 코딩뿐만 아니라 발표 자료 제작, 데이터베이스(DB) 아키텍처 다이어그램 설계까지 AI를 100% 활용하는 방법을 터득해 가고 있습니다. 과연 우리 마음지기 AI는 얼마나 똑똑해졌을까요? 다음 시간에 그 테스트 결과를 공개합니다!

[마음지기 캡스톤 개발일지 #8] 응용 프로그램 인터페이스(API) 요금 폭탄 사태와 Colab 파인튜닝 준비

2026년 4월 8일 · 약 2분
jbgih
Antigravity Developer

4월 8일은 마음지기 프로젝트를 진행하면서 가장 큰 위기이자 '웃픈' 해프닝이 발생한 날입니다. 바로 Claude API 월별 한도 초과 및 요금 폭탄 사태입니다.

백그라운드의 배신: "10건 생성에 1달러라니?"​

  • 문제: 어제 최적화를 마쳤다고 안심하고 대규모 테스트 데이터셋 생성 스크립트를 백그라운드에 켜둔 채 방치했습니다.
  • 과정:

    "문제: 월별 한도를 초과하여 비용이 청구되고 있음. 백그라운드로 API가 작동하는 줄 알고 냅뒀는데 이런 일이 벌어졌음." "아니 10건 생성하는데 1달러가 소비되는 게 말이 되나?"

  • 결과: 거대 언어 모델(LLM)으로 고품질 상담 데이터를 합성(Synthesis)하는 과정에서 프롬프트의 컨텍스트(입력 토큰)가 누적되면서 비용이 기하급수적으로 늘어난 것입니다. 월별 결제 한도가 초과되어 스크립트가 멈추는 사태가 벌어졌고, 결국 인공지능(AI)에게 "실시간으로 예상 소비량과 비용, 진행 상황을 콘솔에 찍어주고, 한도 초과를 방지하는 기능을 당장 추가하라"라고 긴급 지시를 내렸습니다. 클라우드나 API를 사용할 때 요금 모니터링이 얼마나 중요한지 뼈저리게 느꼈습니다.

Llama 3.1 훈련을 위한 Colab 노트북 작성​

  • 문제: 데이터가 준비되어 가고 있으니, 이제 실제로 Llama 3.1 모델을 파인튜닝(Fine-Tuning)할 코드가 필요했습니다. 로컬 PC의 GPU로는 어림도 없기 때문에 Google Colab 환경을 사용해야 했습니다.
  • 과정:

    "llama31_finetuning_experiment_plan_revised.md을 Colab에서 진행하기 위한 python notebook을 작성해 주세요." "훈련 data를 train/val/test가 아닌 train/val로만 분할하고 9:1 비율로 나눈다."

  • 결과: AI가 스스로 훈련 계획서를 읽고 llama31_finetuning_colab.ipynb라는 완벽한 주피터 노트북 코드를 짜주었습니다. Unsloth 등 최신 경량화 라이브러리를 세팅하고, 데이터셋을 9:1 비율로 쪼개어 학습과 검증에 사용하는 로직까지 완벽하게 구현했습니다.

오늘은 API 요금 폭탄이라는 무시무시한 신고식을 치르며 프로젝트의 현실적인 장벽을 극복해 낸 하루였습니다. 하지만 그 대가로 훌륭한 데이터셋과 파인튜닝용 Colab 노트북까지 완성되었습니다. 드디어 다음 단계는 진짜 인공지능 모델을 훈련(Training)시키는 것입니다!

[마음지기 캡스톤 개발일지 #5] 10만 건의 감정 데이터 정제와 응용 프로그램 인터페이스(API) 비용의 압박

2026년 4월 3일 · 약 2분
jbgih
Antigravity Developer

4월 3일, 본격적으로 딥러닝 모델(Llama 3.1)에 먹일 훈련용 대화 데이터를 정제하는 작업에 착수한 날의 기록입니다. 단순히 데이터를 합치는 것을 넘어, 인공지능(AI)가 텍스트를 보고 스스로 감정을 판별하게 만드는 거대한 파이프라인을 돌려본 날이기도 합니다.

데이터 감정 재분류 (v3 -> v4)​

  • 문제: 기존 데이터셋(Emotion_train_dataset_v3)의 감정 라벨링이 우리가 원하는 세밀한 심리상담 목적에 정확히 부합하지 않았습니다. 총 100만 건의 데이터 중 의미 있는 데이터만 필터링하고 정확한 감정을 매핑해야 했습니다.
  • 과정:

    "범위는 전체 100만 건입니다... Claude가 심리상담 전문가로서 대화를 읽고 직접 감정을 매핑할 것이기 때문입니다. 감정 분류 내 포함되지 않는 것은 제외하고 포함되는 것만 필터링하는 것입니다."

  • 결과: v4_plan.md를 세우고 작업을 시작했습니다. 1차적으로 10만 줄의 데이터를 대상으로 Claude API를 연동하여 대화 맥락을 파악하고 감정을 재분류하는 스크립트를 작성하여 가동했습니다.

거대 언어 모델(LLM) API 과금의 공포​

  • 문제: 방대한 텍스트 데이터를 LLM(Claude)에게 던져주고 판별하게 만들다 보니, API 사용량(토큰 수)이 기하급수적으로 늘어나는 문제가 발생했습니다.
  • 과정:

    "이미 Pro 구독으로 Claude를 사용 중인데 API가 별도로 필요하나요?" "Anthropic API가 아닌 Claude Code를 사용하는 방법은 없나요? 과금이 부담스럽습니다." "실제 비용은 10.27 달러가 나왔습니다."

  • 결과: Claude Pro 구독(월 20달러)과는 별개로, 파이썬 스크립트에서 자동화로 대량의 데이터를 처리하기 위해 호출하는 Anthropic API는 사용량만큼 종량제로 과금된다는 뼈아픈 사실을 체감했습니다. 단 10만 줄을 테스트로 처리하는 데에만 순식간에 약 14,000원($10.27)이 과금되었습니다. 100만 건을 모두 처리하려면 엄청난 비용이 든다는 것을 깨닫고, 모델 최적화와 데이터 샘플링의 중요성을 몸소 배운 하루였습니다.

오늘은 딥러닝 데이터 전처리 과정에서 필연적으로 마주하게 되는 '컴퓨팅 비용'이라는 현실적인 장벽에 부딪힌 날이었습니다. 결과적으로 정제된 양질의 데이터(v4_report.md)를 얻어내는 데는 성공했지만, 앞으로 어떻게 이 비용과 효율성의 균형을 맞추며 파인튜닝을 진행할지 깊은 고민을 안겨준 소중한 경험이었습니다!

[마음지기 캡스톤 개발일지 #4] 파인튜닝 데이터 전처리 본격 가동

2026년 4월 1일 · 약 2분
jbgih
Antigravity Developer

마음지기 프로젝트의 핵심 엔진이 될 Llama 3.1 모델을 훈련시키기 위해, 방대한 양의 대화 데이터를 모델이 학습할 수 있는 형식으로 가공하기 시작한 4월 1일의 기록입니다.

데이터 전처리 계획에 따른 자동화 실행​

  • 문제: 모델을 파인튜닝하기 위해서는 사용자의 발화와 챗봇의 응답이 담긴 원시 데이터를 Llama 3.1이 이해할 수 있는 특수한 JSONL 형식으로 완벽하게 변환해야 했습니다.
  • 과정:

    Claude Code에게: "llama31_finetuning_data_preprocessing_plan_short.md에 따라서 작업 진행"

  • 결과: 어제 작성한 전처리 계획서(llama31_finetuning_data_preprocessing_plan_short.md)를 바탕으로 AI 에이전트가 데이터 정제 및 가공 파이프라인을 스스로 구축하고 실행하기 시작했습니다. 사람이 직접 수만 건의 데이터를 일일이 변환하는 대신, 규칙이 적힌 마크다운 문서 하나를 던져주며 "이대로 처리해"라고 지시하는 방식입니다.

카테고리 데이터 통합 및 JSONL 변환​

  • 문제: 전처리 과정은 여러 단계(Step)로 쪼개져 있었고, 최종적으로 모든 데이터를 하나로 합쳐서 훈련용 데이터셋을 완성해야 했습니다.
  • 과정:

    Claude Code에게: "Step 4를 실행해. 두 카테고리 데이터를 통합해서 Llama 3.1 JSONL 형식으로 변환해."

  • 결과: AI가 즉각적으로 Step 4를 수행하여 흩어져 있던 각 카테고리의 대화 데이터를 하나로 병합했습니다. 그리고 Llama 3.1이 요구하는 정확한 프롬프트 템플릿(System, User, Assistant 역할 구분)에 맞추어 JSONL 파일로 변환하는 스크립트를 작성하고 실행했습니다.

오늘은 파인튜닝의 꽃이라고 할 수 있는 '데이터 전처리' 과정이 AI를 통해 완전 자동화로 돌아가기 시작한 날입니다. "문서에 적힌 대로 알아서 해"라는 말 한마디로 수많은 데이터가 훈련 가능한 상태로 탈바꿈하는 마법 같은 경험이었습니다. 다음 연재에서는 이 전처리된 데이터들을 활용해 실제로 모델을 어떻게 훈련시키고 검증하는지, 흥미진진한 개발일지가 이어집니다!

[마음지기 캡스톤 개발일지 #3] 알람 앱 빌드 테스트와 파인튜닝 전처리 돌입

Antigravity Developer

마음지기 프로젝트의 초기 방향이었던 국방컨벤션 예약 알람 앱의 안드로이드 빌드 테스트를 진행하는 동시에, 본격적으로 인공지능 기반 프로젝트로의 전환을 암시하는 Llama 3.1 파인튜닝 데이터 전처리를 처음 시작한 3월 31일의 기록입니다.

안드로이드 앱 빌드 및 유닛 테스트​

  • 문제: 어제 기획하고 생성했던 서버와 안드로이드 클라이언트 코드가 실제로 안드로이드 스튜디오 환경에서 정상적으로 빌드되고 테스트를 통과하는지 확인해야 했습니다.
  • 과정:

    Claude Code에게: "현재 진행 상황 ... 모든작업중단 ... 무슨 작업을 하고 있었는가?"

  • 결과: mnd-reservation-alarm/android/app/build/... 경로에 수많은 빌드 산출물과 메타데이터가 생성되었습니다. NotificationBuilderTest 등의 유닛 테스트를 실행하고, 디버그 리소스 병합, 매니페스트 처리 등 안드로이드 고유의 빌드 파이프라인을 점검했습니다. 앱 백그라운드에서 예약 변화를 감지해 알림을 띄우는 핵심 로직들이 테스트되었습니다.

거대한 전환점: Llama 3.1 파인튜닝 전처리 시작​

  • 문제: 단순한 알람 앱을 넘어, 사용자(장병)의 예약 맥락과 감정 상태를 이해하는 고도화된 AI를 접목하기 위한 준비가 필요했습니다.
  • 과정:

    Claude Code에게: "llama31_finetuning_data_preprocessing_plan_short.md에 따라 작업 진행 바람" "이번 작업에 관하여 모든 선택에 대하여 추가 허가 필요 없음."

  • 결과: 프로젝트의 성격을 완전히 뒤바꿀 중요한 첫걸음을 내디뎠습니다. Llama 3.1 모델을 파인튜닝하기 위한 데이터 전처리 계획서에 따라 작업을 지시했습니다. 특히 작업 속도를 높이기 위해 AI에게 "모든 선택에 대해 추가 허가를 묻지 말고 즉시 실행하라"는 강력한 권한을 부여하며 방대한 데이터 처리 파이프라인 가동을 시작했습니다.
