Antigravity Developer

5월 19일과 20일 이틀 동안은 3차 파인튜닝(fine_tuning_3)의 평가 자동화와 더불어, 실제 앱(App) 서비스 구축을 위한 백엔드/프론트엔드 기능 고도화 작업이 병렬로 진행되었습니다.

3차 파인튜닝 (fine_tuning_3) 마무리와 자동화 스크립트​

이전 파인튜닝에서 얻은 인사이트를 바탕으로, 지식그래프와 온톨로지 개념을 의식하며 세팅했던 3차 파인튜닝의 학습이 완료되었습니다.

"fine_tuning_3 폴더의 실험 모델들 중 Best Eval을 가진 체크포인트를 선별하여 adapter 폴더 내 파일을 교체하고 결과를 보고해 줘." "fine_tuning_3에서도 추론과 평가를 병렬로 진행하는 run_test_20_30.sh 파일을 작성해 주세요."

이전처럼 사람이 일일이 폴더를 뒤지며 체크포인트를 복사하는 대신, 인공지능(AI)에게 스크립트를 짜도록 지시하여 가장 성능이 좋은 모델 가중치(Best Checkpoint)를 자동으로 추출해 adapter 폴더에 세팅했습니다. 그리고 병렬 추론 스크립트인 run_test_20_30.sh를 실행하여 4개의 Alias 모델에 대한 평가를 백그라운드 서버에 던져두었습니다.

백엔드/프론트엔드: 챗봇 DB 저장과 게시판 기능 완성​

모델이 서버에서 열심히 추론을 돌리는 동안, 로컬 환경에서는 mental-health DB와 앱 연동 작업에 박차를 가했습니다.

"seed_data.sql 정보 요약. users의 pw가 무엇이지? Test1234! 인가? 현재 내가 이 sql을 적용하려던 db가 뭐였지?"

지난번 401 Unauthorized 에러로 골치를 썩였던 로그인 문제를 뚫어내기 위해 seed_data.sql을 뜯어보며 비밀번호 해싱과 유저 데이터를 철저히 검증했습니다.

그 결과, 5월 20일 오후 뜻깊은 Git 커밋(Commit) 하나를 남길 수 있었습니다. feat: 챗봇 DB 저장, 게시판 페이지네이션, 감정일기 필터 추가

드디어 저희가 파인튜닝한 거대 언어 모델(LLM) 챗봇의 대화 기록이 DB에 정식으로 저장되기 시작했습니다! 더불어 사용자들끼리 소통할 수 있는 커뮤니티 게시판의 페이지네이션(Pagination) 기능과, 매일매일의 기분을 기록하는 감정일기 필터 기능까지 성공적으로 프론트엔드에 얹혔습니다.

눈에 보이지 않던 거대한 파인튜닝 모델이 비로소 모바일 앱이라는 예쁜 그릇에 담기기 시작한 감격스러운 순간이었습니다.

[마음지기 캡스톤 개발일지 #16] 치명적 실수와 2차 파인튜닝, 그리고 React Native 앱 첫 구동

2026년 5월 8일 · 약 2분
jbgih
Antigravity Developer

5월 8일은 그동안 뽑아낸 파인튜닝 결과들을 바탕으로 캡스톤디자인 중간 발표 자료(PPT)를 만들던 날이었습니다. 하지만 기분 좋게 슬라이드를 채워나가던 중, 등골이 서늘해지는 엄청난 실수를 발견하고 말았습니다.

LoRA 하이퍼파라미터의 치명적 실수 발견​

PPT에 들어갈 모델 구조도와 하이퍼파라미터 정보를 인공지능(AI)와 함께 다듬고 있었습니다.

"파인튜닝 결과 예시를 보면 base model보다 답변이 짧아졌습니다. 이는 LoRA의 r을 8로 하고 alpha를 16으로 해서 중간 feature를 너무 줄이다 보니 답변이 짧아졌다고 생각이 드는데..." "아니 a/r 이었어? 나는 r/a라고 알고 있었는데...??? 나는 정말 LoRA를 욕심쟁이로 반영한 거구나..."

LoRA 파인튜닝 시 alpha 값은 보통 rank 값과 동일하거나 2배로 주는 것이 정석입니다. 그런데 계산식 적용 비율을 완전히 반대로 착각하여, 가중치 업데이트가 극단적으로 억눌리거나 과하게 튕겨버리게 세팅해 버린 것입니다. 어쩐지 파인튜닝된 모델의 답변 길이가 뚝뚝 끊기고 짧아지더라니, 원인은 바로 제 손끝에 있었습니다.

2차 파인튜닝 (fine_tuning_2) 결단​

이미 1차 결과가 나왔지만, 완벽한 '마음지기'를 위해 이대로 넘어갈 순 없었습니다. 즉시 fine_tuning_2 폴더를 파고 2차 파인튜닝을 결단했습니다.

"이번에 사용할 모델은 HCX-Text-1p5B, Llama33-70B, Qwen35-9B 입니다. MIG-0에서는 rank는 16, alpha는 16으로, MIG-1에서는 rank=16, a=8로 설정하여 학습 진행해 줘." "Daily_train_dataset.jsonl에서 가장 긴 데이터 상위 2000개를 뽑아서 Daily_train_dataset_long.jsonl이란 제목의 파일로 생성해 주세요."

답변이 짧아지는 현상을 방지하기 위해 가장 텍스트 길이가 긴 상위 2000개의 데이터셋만을 따로 추출하고, MIG(Multi-Instance GPU) 자원을 나누어 rank와 alpha 비율에 따른 성능 차이를 직접 비교하는 병렬 학습을 새롭게 돌리기 시작했습니다.

백엔드 모델이 도는 동안, 프론트엔드(앱) 개발 착수​

모델이 다시 학습의 굴레에 빠진 동안, 저는 손을 놓고 있지 않았습니다. 드디어 실제 사용자들이 '마음지기'를 만나게 될 프론트엔드 앱 개발에 착수했습니다!

"maeum-app을 구동하기 위해 QR코드를 시현해야 하는데... npx go start를 입력해도 에러 메시지만 시현돼. 어떻게 그리고 어디에 QR코드가 시현될 수 있을까?"

React Native(Expo)를 이용해 maeum-app 프로젝트를 생성하고 로컬 서버를 띄워 스마트폰과 연결하려 고군분투했습니다. 엉뚱하게 npx go start를 치며 헤매기도 했지만, 마침내 Expo QR 코드를 띄우고 앱 아이콘(assets/logo.png)을 세팅하는 데 성공했습니다. 백엔드의 두뇌(AI)와 프론트엔드의 얼굴(App)이 동시에 만들어지고 있는 가슴 벅찬 하루였습니다.

[마음지기 캡스톤 개발일지 #7] 합성 데이터(v5) 생성 최적화와 프론트엔드 연동

2026년 4월 7일 · 약 2분
jbgih
Antigravity Developer

4월 7일은 팀원이 구축한 프론트엔드(mental-health) 코드를 로컬 환경에서 실행해 보며 통합을 시도한 날이자, 인공지능(AI)를 활용해 부족한 상담 데이터를 6만 건이나 새롭게 '합성(Synthesis)'해내는 거대한 스크립트를 가동한 날입니다.

부족한 데이터를 채워라: AI 합성 데이터(v5) 생성​

  • 문제: 기존에 정제한 데이터(v4)만으로는 특정 감정이나 세밀한 상담 시나리오가 부족했습니다. 이를 해결하기 위해 Claude 응용 프로그램 인터페이스(API)를 사용하여 Llama 3.1 훈련 포맷(System, User, Assistant)에 맞는 가상의 고품질 상담 대화를 6만 건 생성하고자 했습니다.
  • 과정:

    "Claude가 자체적으로 만든 v5의 데이터셋을 만들고자 합니다. 계획을 세워주세요." "저는 jsonl 포맷(system, user, assistant)에 맞게 Claude가 생성해 주는 6만 건의 데이터셋을 구하고 싶습니다."

  • 결과: v5_plan.md를 세우고 데이터를 생성하기 시작했습니다. 하지만 이내 API 호출 비용이 또다시 발목을 잡았습니다.

끝나지 않는 비용과의 전쟁: 프롬프트 최적화​

  • 문제: 데이터 6만 건을 AI에게 창작시키려다 보니 며칠 전 겪었던 비용 문제가 재현되었습니다. 스크립트 실행 도중 크레딧 10달러가 순식간에 증발했습니다.
  • 과정:

    "step8_generate_v5_optimized.py 이대로 진행하면 토큰 사용량이 줄어드나요?" "현재 크레딧의 $10를 소비했는데 저 정도 progress 진행 중입니다."

  • 결과: AI에게 비용을 절감할 수 있는 프롬프트 엔지니어링과 코드 최적화(step8_generate_v5_optimized.py)를 지시하여 출력 토큰의 낭비를 막고, 생성 진행률을 안전하게 저장하는 로직을 추가했습니다.

팀원의 프론트엔드 코드 인수인계 및 실행​

  • 과정:

    "이 프로젝트는 팀 동료가 만든 프로젝트로 제가 실행하려면 어떻게 해야 하나요?" "4번 데이터베이스(DB) 마이그레이션 중 오류 발생..." "6단계 frontend까지 실행 완료. 종료 방법과 다시 실행 시 간단한 절차를 알려주세요."

  • 결과: 팀원이 작성해 둔 mental-health 리포지토리를 넘겨받아 로컬에서 실행하고 DB 마이그레이션 오류를 해결했습니다. 이제 백엔드 AI 모델과 프론트엔드가 만날 준비가 되었습니다.

오늘은 데이터 전처리를 넘어, AI가 AI를 학습시킬 교과서(데이터)를 직접 집필하게 만드는(Synthetic Data Generation) 최신 딥러닝 트렌드를 직접 구현해 본 뜻깊은 날이었습니다. 쏟아지는 과금의 공포 속에서 최적화를 이뤄내고, 프론트엔드 서버까지 무사히 띄워낸 하루였습니다!
