  • 실제 마주친 3대 돌발 오류 해결:
    1. 상호 출자 관계망 순회 시 발생한 순환 참조(Cycle) 무한 재귀 에러 ➔ NetworkX 강결합 컴포넌트(SCC) 축약 알고리즘으로 해결.
    2. 입찰 직전 급조된 유령 법인 미탐 ➔ 계약일 기준 180일 미만 신설 법인 탐지기 탑재.

  • 알림 피로(Alert Fatigue) 극복: 연간 수십만 건의 공공 조달 데이터 중 80~95%를 차지하는 단순 소모품 구매 노이즈를 제거하기 위해 **3차원 표적 분할 매니저(SectorPartitionManager)**를 설계, 85% 이상의 노이즈를 사전 필터링하고 고위험군에 AI 컴퓨팅 파워를 집중시켰습니다.
  • 예상했던 난제와 사전 예방: 공공데이터포털의 잦은 타임아웃과 예고 없는 API 규격 변경에 대비하여, 외부 수신 계층과 감사 엔진 사이에 SQLite 격리 버퍼 큐와 지수 백오프(Exponential Backoff) 재시도 계층을 사전 구축했습니다.
  • 실제 마주친 3대 돌발 오류 해결:

    3. 실시간 동기화 시 중복 계약 적재 및 중복 경보 발행 ➔ SHA-256 Fingerprint Hash 기반 멱등성(Idempotent) 파이프라인으로 해결.

[스탠포드 CS146S #7] 대규모 코드 리뷰 자동화: AST 기반 린터, 보안 오염 분석(Taint Analysis), 그리고 LLM PR 리뷰어

2026년 10월 28일 · 약 9분
Jaybee
AI & Robotics Engineer

스탠포드 대학교 CS146S (현대 소프트웨어 개발자: The Modern Software Developer) 심층 분석 시리즈의 7번째 강의에 오신 것을 환영합니다.

지난 강의에서 우리는 프로덕션 런타임 장애를 실시간으로 추적하고 복구하는 eBPF 및 AI SRE 파이프라인을 다루었습니다. 하지만 노련한 엔지니어링 리더들이 입을 모아 말하듯, 가장 비용 효율적인 버그는 애초에 메인 브랜치에 병합(Merge)되지 않은 버그입니다.

빠르게 성장하는 테크 기업에서 풀 리퀘스트(PR) 코드 리뷰는 소프트웨어의 품질, 보안, 아키텍처 일관성을 지키는 핵심 수문장입니다. 그러나 조직의 규모가 커질수록 인간 개발자 간의 피어 리뷰는 필연적으로 거대한 병목으로 변질됩니다. 시니어 엔지니어들은 매주 15~20시간을 PR 검토에 쏟아부으며 들여쓰기, 네이밍 규칙, 임포트 순서 같은 사소한 꼬투리 잡기(Bikeshedding)에 인지적 에너지를 낭비합니다. 반면 정작 1,000줄이 넘어가는 방대한 변경 사항 앞에서는 **리뷰 피로(Review Fatigue)**에 빠져 대충 "LGTM(Looks Good To Me)"을 찍어버려, 치명적인 동시성 버그나 SQL 인젝션, 아키텍처 붕괴를 그대로 통과시키고 맙니다.

오늘 강의에서 스탠포드 교수진은 **대규모 자동화 코드 리뷰(Automated Code Review at Scale)**의 완성형 청사진을 제시합니다. 추상 구문 트리(AST) 린터, 프로시저 간 보안 오염 분석(Taint Analysis), 그리고 자율 LLM PR 리뷰어를 3단계 계층 구조로 결합하여 인간의 수작업 리뷰 피로를 90% 이상 덜어내면서도 취약점 탐지율을 극대화하는 방법을 심층 분석합니다.

GitHub Pages 커스텀 도메인 & Cloudflare DNS 무중단 연동 가이드

2026년 10월 21일 · 약 6분
Jaybee

개발자라면 누구나 한 번쯤 GitHub Pages의 무료 서브도메인(username.github.io/project)을 이용해 블로그를 운영해 보았을 것입니다. Git 푸시 한 번으로 전 세계에 정적 사이트가 배포되고 서버 유지비가 들지 않는다는 점은 초기 개발자 블로그에 최고의 장점입니다.

하지만 전문적인 기술 브랜딩과 구글 애드센스(Google AdSense) 수익화를 준비하는 순간 타협할 수 없는 기술적 한계에 부딪힙니다. 구글 애드센스는 *.github.io와 같은 무료 2차 서브도메인의 사이트 등록 및 심사 신청을 정책적으로 원천 차단하기 때문입니다. 또한 포털 검색엔진에서 쌓이는 도메인 지수(Domain Authority)가 깃허브가 아닌 온전한 '내 자산'으로 누적되게 하려면 반드시 **독립 커스텀 도메인(Apex Domain, 예: globaldevlog.com)**이 필수적입니다.

정적 사이트(SSG) 엔지니어링 시리즈의 첫 번째 편인 이번 글에서는, 기존 jbjihwan.github.io/global_blog에서 독립 도메인 https://globaldevlog.com으로의 무중단 마이그레이션을 완수한 Porkbun + Cloudflare + GitHub Pages 3계층 고가용성 아키텍처와 DNS 설정 실무를 완벽하게 정리합니다.

GitHub Pages 애드센스 승인 가이드: 커스텀 도메인 & ads.txt 연동

2026년 10월 20일 · 약 6분
Jaybee
AI & Robotics Engineer

개발자 블로그를 GitHub Pages의 무료 서브도메인(username.github.io/project)에 배포하여 운영하는 것은 간편하지만, 전문적인 브랜딩과 수익화를 시작하는 순간 거대한 벽에 부딪힙니다. 구글 애드센스는 *.github.io와 같은 무료 서브도메인의 사이트 등록을 원천 차단하기 때문입니다. 애드센스 게시자 심사를 통과하고 검색엔진 도메인 점수(Domain Authority)를 쌓으려면 반드시 독자적인 **독립 커스텀 도메인(Apex Domain)**이 필요합니다.

정적 사이트(SSG)의 도메인 이전은 단순한 DNS 주소 변경에 그치지 않습니다. 도메인 등록기관(Registrar)의 네임서버 위임, 엣지 SSL 암호화, CNAME 평탄화(Flattening), Docusaurus 빌드 파이프라인의 루트 재매핑, ads.txt 호스팅, 그리고 각 검색엔진 포털의 특유한 UI 트랩을 모두 해결해야 합니다.

본 포스팅에서는 기존 jbjihwan.github.io/global_blog에서 독립 도메인 https://globaldevlog.com으로의 무중단 이전 아키텍처와 구글 서치 콘솔, 네이버 서치어드바이저, 빙 웹마스터 도구의 실제 트러블슈팅 과정을 상세히 정리합니다.
