[마음지기 캡스톤 개발일지 #8] 응용 프로그램 인터페이스(API) 요금 폭탄 사태와 Colab 파인튜닝 준비

2026년 4월 8일 · 약 2분
jaybee
Maeumjigi Developer

4월 8일은 마음지기 프로젝트를 진행하면서 가장 큰 위기이자 '웃픈' 해프닝이 발생한 날입니다. 바로 Claude API 월별 한도 초과 및 요금 폭탄 사태입니다.

백그라운드의 배신: "10건 생성에 1달러라니?"​

  • 문제: 어제 최적화를 마쳤다고 안심하고 대규모 테스트 데이터셋 생성 스크립트를 백그라운드에 켜둔 채 방치했습니다.
  • 과정:

    "문제: 월별 한도를 초과하여 비용이 청구되고 있음. 백그라운드로 API가 작동하는 줄 알고 냅뒀는데 이런 일이 벌어졌음." "아니 10건 생성하는데 1달러가 소비되는 게 말이 되나?"

  • 결과: 거대 언어 모델(LLM)으로 고품질 상담 데이터를 합성(Synthesis)하는 과정에서 프롬프트의 컨텍스트(입력 토큰)가 누적되면서 비용이 기하급수적으로 늘어난 것입니다. 월별 결제 한도가 초과되어 스크립트가 멈추는 사태가 벌어졌고, 결국 인공지능(AI)에게 "실시간으로 예상 소비량과 비용, 진행 상황을 콘솔에 찍어주고, 한도 초과를 방지하는 기능을 당장 추가하라"라고 긴급 지시를 내렸습니다. 클라우드나 API를 사용할 때 요금 모니터링이 얼마나 중요한지 뼈저리게 느꼈습니다.

Llama 3.1 훈련을 위한 Colab 노트북 작성​

  • 문제: 데이터가 준비되어 가고 있으니, 이제 실제로 Llama 3.1 모델을 파인튜닝(Fine-Tuning)할 코드가 필요했습니다. 로컬 PC의 GPU로는 어림도 없기 때문에 Google Colab 환경을 사용해야 했습니다.
  • 과정:

    "llama31_finetuning_experiment_plan_revised.md을 Colab에서 진행하기 위한 python notebook을 작성해 주세요." "훈련 data를 train/val/test가 아닌 train/val로만 분할하고 9:1 비율로 나눈다."

  • 결과: AI가 스스로 훈련 계획서를 읽고 llama31_finetuning_colab.ipynb라는 완벽한 주피터 노트북 코드를 짜주었습니다. Unsloth 등 최신 경량화 라이브러리를 세팅하고, 데이터셋을 9:1 비율로 쪼개어 학습과 검증에 사용하는 로직까지 완벽하게 구현했습니다.

오늘은 API 요금 폭탄이라는 무시무시한 신고식을 치르며 프로젝트의 현실적인 장벽을 극복해 낸 하루였습니다. 하지만 그 대가로 훌륭한 데이터셋과 파인튜닝용 Colab 노트북까지 완성되었습니다. 드디어 다음 단계는 진짜 인공지능 모델을 훈련(Training)시키는 것입니다!

[마음지기 캡스톤 개발일지 #6] 전처리 최종 보고서 자동화와 프론트엔드 킥오프

2026년 4월 5일 · 약 2분
jaybee
Maeumjigi Developer

4월 5일은 그동안 진행해 온 고된 데이터 전처리 과정(v1~v4)을 갈무리하는 최종 보고서를 작성하고, 동시에 본격적으로 마음지기 웹 서비스의 얼굴이 될 프론트엔드 프로젝트를 킥오프한 날입니다.

마크다운부터 DOCX, 그래프 생성까지 완벽한 문서화​

  • 문제: 지도교수님과 팀원들에게 그동안의 방대한 전처리 과정을 시각적으로 이해하기 쉽게 공유해야 했습니다.
  • 과정:

    Claude Code에게: "데이터 전처리 과정(v1, v2, v3, v4)을 요약하여 최종보고서를 작성해주세요... 각 v별 대표 예시 추가해 줘." "이 md파일을 docx 파일로 변경해주세요... 그래프로 표현 가능한 것들은 그래프로 추가해서 만들어줘."

  • 결과: 놀랍게도 인공지능(AI)는 그동안 작업했던 파이썬 코드와 JSON 데이터를 분석하여 핵심 요약 보고서를 마크다운으로 뚝딱 써냈습니다. 여기에 그치지 않고, 파이썬 라이브러리(python-docx, matplotlib)를 스스로 설치하고 스크립트를 짜더니 마크다운을 깔끔한 워드(DOCX) 파일로 변환하고 감정 분포 그래프까지 그려서 삽입해 주었습니다! 문서 작업에 허비되는 시간을 획기적으로 줄인 순간이었습니다.

Next.js 기반 프론트엔드 프로젝트 킥오프​

  • 문제: 인공지능 모델 훈련과 별개로, 사용자들이 실제로 챗봇과 대화할 수 있는 웹 인터페이스가 필요했습니다.
  • 과정: (백그라운드 작업) 사용자(장병)에게 친숙하고 빠른 UI를 제공하기 위해 Next.js 기반의 프론트엔드 프로젝트 세팅을 지시했습니다.
  • 결과: maeumjigi/frontend/ 경로에 package.json, tsconfig.json 등이 생성되며 최신 트렌드인 Next.js 기반의 프론트엔드 환경이 성공적으로 세팅되었습니다.

오늘은 AI의 능력이 단순히 코딩을 넘어 '문서 요약, 그래프 시각화, DOCX 파일 생성'이라는 훌륭한 사무보조 역할까지 완벽하게 수행할 수 있음을 증명한 날이었습니다. 데이터 전처리라는 큰 산을 하나 넘고, 이제 본격적으로 사용자와 만날 프론트엔드 개발의 닻을 올렸습니다!

[마음지기 캡스톤 개발일지 #4] 파인튜닝 데이터 전처리 본격 가동

2026년 4월 1일 · 약 2분
jaybee
Maeumjigi Developer

마음지기 프로젝트의 핵심 엔진이 될 Llama 3.1 모델을 훈련시키기 위해, 방대한 양의 대화 데이터를 모델이 학습할 수 있는 형식으로 가공하기 시작한 4월 1일의 기록입니다.

데이터 전처리 계획에 따른 자동화 실행​

  • 문제: 모델을 파인튜닝하기 위해서는 사용자의 발화와 챗봇의 응답이 담긴 원시 데이터를 Llama 3.1이 이해할 수 있는 특수한 JSONL 형식으로 완벽하게 변환해야 했습니다.
  • 과정:

    Claude Code에게: "llama31_finetuning_data_preprocessing_plan_short.md에 따라서 작업 진행"

  • 결과: 어제 작성한 전처리 계획서(llama31_finetuning_data_preprocessing_plan_short.md)를 바탕으로 AI 에이전트가 데이터 정제 및 가공 파이프라인을 스스로 구축하고 실행하기 시작했습니다. 사람이 직접 수만 건의 데이터를 일일이 변환하는 대신, 규칙이 적힌 마크다운 문서 하나를 던져주며 "이대로 처리해"라고 지시하는 방식입니다.

카테고리 데이터 통합 및 JSONL 변환​

  • 문제: 전처리 과정은 여러 단계(Step)로 쪼개져 있었고, 최종적으로 모든 데이터를 하나로 합쳐서 훈련용 데이터셋을 완성해야 했습니다.
  • 과정:

    Claude Code에게: "Step 4를 실행해. 두 카테고리 데이터를 통합해서 Llama 3.1 JSONL 형식으로 변환해."

  • 결과: AI가 즉각적으로 Step 4를 수행하여 흩어져 있던 각 카테고리의 대화 데이터를 하나로 병합했습니다. 그리고 Llama 3.1이 요구하는 정확한 프롬프트 템플릿(System, User, Assistant 역할 구분)에 맞추어 JSONL 파일로 변환하는 스크립트를 작성하고 실행했습니다.

오늘은 파인튜닝의 꽃이라고 할 수 있는 '데이터 전처리' 과정이 AI를 통해 완전 자동화로 돌아가기 시작한 날입니다. "문서에 적힌 대로 알아서 해"라는 말 한마디로 수많은 데이터가 훈련 가능한 상태로 탈바꿈하는 마법 같은 경험이었습니다. 다음 연재에서는 이 전처리된 데이터들을 활용해 실제로 모델을 어떻게 훈련시키고 검증하는지, 흥미진진한 개발일지가 이어집니다!
